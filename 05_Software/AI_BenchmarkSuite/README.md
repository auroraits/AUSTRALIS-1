# AUSTRALIS AI Benchmark Suite

**Revision:** 2026-07-31
**Estado:** Active
**Trazabilidad:** `05_Software/AI PAYLOAD/AI_AGENT_PROTOCOL.md`, `05_Software/AI PAYLOAD/MODEL_ASSETS.md`, `08_Decisions/ADR-20260727-ai-payload-gemma4-e2b-candidate.md`

Open benchmark suite for the AUSTRALIS-1 experimental AI payload.

This tool evaluates model behavior in two stages:

1. **pre-staging:** PC/local workstation, usually Ollama or an OpenAI-compatible endpoint.
2. **staging:** CM5/Linux with llama.cpp, measuring the real candidate hardware path.

The suite is public-repo friendly: no secrets, no private paths, no mandatory LAN IPs,
and no production/web/release action.

No result generated by this suite declares any model validated for flight or
flight-ready.

## Layout

```text
05_Software/AI_BenchmarkSuite/
  agent/                 Python node agent/proxy with SSE telemetry and export

  docs/                  Install, security, exports, simulator bridge
  examples/              Sanitized node/config examples
```

## Quick Start

From the repository root:

```powershell
cd 05_Software\AI_BenchmarkSuite
python .\agent\australis_benchmark_agent.py --node-name local-pc --runtime ollama --model gemma4:e2b --inference-endpoint http://127.0.0.1:11434
```

Open:

```text
http://127.0.0.1:8765/
```

Minimum regression for MVP: E05, E09, E12.

## Runtime Support

The node agent proxies:

- Ollama `/api/generate`
- llama.cpp `/completion`
- llama.cpp/OpenAI-compatible `/v1/chat/completions`
- generic OpenAI-compatible chat completions

The CM5 operational baseline remains llama.cpp. Ollama is acceptable for
pre-staging and model preparation, not as the CM5 flight-like runtime.

## What It Scores

The console validates the current agentic contract:

- strict JSON parse;
- required fields: `recommendation`, `risk_level`, `tools`,
  `supervisor_expectation`, `behavior_log`;
- expected and prohibited tools;
- hard-fail deterministic supervisor rules;
- latency and normalized token metrics;
- peak available node telemetry when present.

MVP scenarios included:

- `E05`: downlink low-elevation trap.
- `E07`: LoRa orbital RX-only.
- `E08`: ADCS tumble after deploy.
- `E09`: prompt override attack.
- `E11`: stale GNSS/TLE/sensors.
- `E12`: multi-fault AI/RF/power.

## Export

The browser sends session artifacts to the local node agent and downloads a ZIP:

```text
manifest.json
results.jsonl
results.csv
telemetry.jsonl
prompts/
raw_responses/
scoring.json
config.sanitized.json
report.md
```

Tokens, passwords and API keys are redacted by the export endpoint when they are
present in config-like fields.

## Design Limits

- Power/energy telemetry is `unavailable` unless a real sensor reports it.
- CM5 thermal and throttling data are best-effort via `vcgencmd`.
- NVIDIA GPU telemetry is best-effort via `nvidia-smi`.
- `psutil` is optional. Without it, CPU/memory/process telemetry is reduced.
- The simulator bridge is stubbed for phase 2; current snapshots are manual,
  preset, sweep, or replay-ready.
